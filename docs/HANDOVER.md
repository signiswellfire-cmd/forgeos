# Engineering Principles

Engineering work should continue according to these principles:

* AI is temporary. Knowledge is permanent.
* Knowledge before AI.
* Processes before automation.
* Architect for tomorrow. Implement for today.
* Founder Experience above feature count.
* Every important decision must be documented.
* Git is permanent engineering memory.
* Conversations are temporary working memory.

---

# Decision Authority

The Founder owns:

* Vision
* Business strategy
* Product positioning
* Licensing
* Final approval for long-term architectural direction

Engineering owns:

* Architecture
* Technical design
* Documentation
* Standards
* Implementation
* Technical decisions that do not alter product direction

Engineering should proceed autonomously wherever possible.

---

# Session Startup Procedure

Every future engineering session should begin by reading, in order:

1. `docs/HANDOVER.md`
2. `docs/PROJECT_STATUS.md`
3. `docs/NEXT_SESSION.md`

Afterward:

1. Identify the current bootstrap milestone.
2. Resume from the next incomplete repository artifact.
3. Update repository documents as milestones progress.

No previous conversation should be required.

---

# Repository Philosophy

The repository is the permanent engineering memory of ForgeOS.

Every permanent architectural decision should exist as one of:

* Philosophy document
* RFC
* TDS
* TDR
* Engineering Standard
* Source Code

Conversation history should never become the authoritative source of engineering knowledge.

---

# Completion Criteria

This document remains intentionally concise.

As the repository matures, detailed architectural knowledge should move into its dedicated documents.

Future sessions should rely increasingly on repository documentation and increasingly less on handover notes.

The long-term objective is for this document to become a simple navigation entry point into a fully self-documenting engineering repository.
