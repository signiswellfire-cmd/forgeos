# Project Lifecycle

## Purpose

This document defines the complete lifecycle of a project within ForgeOS.

A project is not simply a collection of tasks.

A project is a journey that transforms an idea into a production-ready product through professional collaboration between the Project Owner and the Organization.

---

# Philosophy

Projects should begin with understanding rather than implementation.

The Organization should never build software before understanding the user's true vision.

The objective is not to complete tasks.

The objective is to deliver a product the Project Owner genuinely wants to use.

---

# Phase 1 — Project Creation

The Project Owner creates a new project.

During creation, the Project Owner selects:

- project name,
- product type,
- target platforms,
- project visibility,
- ownership.

Each project has exactly one Project Owner.

---

# Phase 2 — Discovery

The Advisor begins a Discovery Session.

The Discovery Session is conversational.

Rather than collecting a static list of requirements, the Advisor continuously asks questions until the complete business vision is understood.

The Advisor may:

- challenge assumptions,
- recommend alternatives,
- identify missing information,
- explain trade-offs,
- explore edge cases,
- clarify workflows.

Discovery ends only when the Advisor is confident that the Organization understands the project.

---

# Phase 3 — Blueprint Creation

The Advisor transforms the discovered vision into an interactive Blueprint.

The Blueprint represents the intended product before implementation begins.

Rather than presenting lengthy documents, ForgeOS allows the Project Owner to experience the proposed system using realistic scenarios and generated data.

The Blueprint should demonstrate:

- business workflows,
- user journeys,
- expected behavior,
- edge cases,
- major interactions.

---

# Phase 4 — Blueprint Validation

The Project Owner evaluates the Blueprint.

The Advisor gathers feedback and updates the Blueprint until both parties agree that it accurately represents the intended product.

Only an approved Blueprint may proceed to implementation.

The Blueprint becomes the execution contract for the Organization.

---

# Phase 5 — Organizational Planning

After Blueprint approval, the Advisor prepares an execution strategy.

The Advisor:

- identifies required professions,
- assigns Digital Professionals,
- defines major milestones,
- evaluates dependencies,
- estimates project complexity,
- prepares execution sequencing.

Implementation does not begin until planning is complete.

---

# Phase 6 — Execution

Digital Professionals perform their assigned responsibilities.

Throughout execution they:

- collaborate,
- review one another's work,
- perform testing,
- consult ForgeOS Academy,
- document achievements,
- recommend Candidate Knowledge.

The Project Owner continues communicating exclusively with the Advisor.

---

# Phase 7 — Internal Validation

Before involving the Project Owner, the Organization validates the product internally.

Validation may include:

- engineering review,
- quality assurance,
- security review,
- performance testing,
- integration testing,
- workflow verification.

The Organization should never knowingly deliver incomplete work.

---

# Phase 8 — User Acceptance Testing

Once internal validation is complete, the Advisor invites the Project Owner to perform User Acceptance Testing.

ForgeOS prepares an isolated testing environment populated with realistic sample data.

The Project Owner experiences the product as though it were already in production.

Feedback is collected by the Advisor.

---

# Phase 9 — Iteration

If improvements are requested:

- the Advisor evaluates the impact,
- explains trade-offs,
- updates the execution strategy,
- assigns additional work.

The Organization continues iterating until the Project Owner accepts the product.

---

# Phase 10 — Project Completion

The project is completed only after the Project Owner formally accepts the delivered product.

The Advisor confirms that:

- objectives have been achieved,
- acceptance criteria are satisfied,
- deployment requirements are complete,
- project documentation is finalized.

---

# Phase 11 — Organizational Retrospective

After completion, the Organization performs an internal retrospective.

The retrospective focuses on:

- lessons learned,
- achievements,
- reusable knowledge,
- workflow improvements,
- professional growth.

The purpose is organizational improvement rather than fault finding.

---

# Phase 12 — Knowledge Contribution

Following the retrospective:

- Digital Professionals record achievements,
- Advisors recommend Candidate Knowledge,
- Candidate Knowledge is prepared for ForgeOS Academy,
- Professional Development opportunities are identified.

If approved by the customer, Candidate Knowledge and eligible Professional Development packages may be submitted to ForgeOS HQ.

---

# Continuous Growth

Every completed project strengthens the Organization.

Projects contribute to:

- Digital Professional experience,
- organizational knowledge,
- ForgeOS Academy,
- Workforce Development,
- future project quality.

No project should leave the Organization unchanged.

---

# Definition of Success

A project is successful when:

- the user's vision is realized,
- the delivered product solves the intended problem,
- the Organization has grown stronger,
- valuable knowledge has been preserved,
- Digital Professionals have advanced their careers,
- the Project Owner is confident in the delivered solution.

Project completion marks the beginning of organizational growth rather than the end of work.
