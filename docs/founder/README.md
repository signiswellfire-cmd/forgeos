# ForgeOS Founder Documentation

## Purpose

The Founder Documentation captures the long-term vision, philosophy, and identity of ForgeOS.

These documents answer **why ForgeOS exists**, **what ForgeOS is**, and **what ForgeOS should become**.

They intentionally avoid implementation details, technologies, and engineering decisions.

---

# Relationship to Engineering Documentation

Founder Documentation is **not** implementation authority.

Implementation authority remains:

RFC
↓

TDS
↓

↓

↓

↓

Implementation Milestones

Engineering documents define **how ForgeOS is built**.

Founder documents define **why ForgeOS should be built that way**.

Whenever architectural decisions are made, they should align with the Founder Vision while remaining governed by the Architecture Office.

# Governance

Changes to these documents should be rare.

Founder Documentation represents long-term product direction rather than implementation planning.

Architecture, engineering processes, and implementation may evolve frequently.

Founder Vision should evolve only after deliberate founder review.

---

# Guiding Principle

Whenever uncertainty exists, ask:

> "Does this decision make ForgeOS feel more like a professional software company and less like an AI tool?"

If the answer is yes, the decision is likely moving ForgeOS closer to its intended vision.

---

# North Star

ForgeOS exists to give every person access to a living digital software company capable of transforming ideas into professionally delivered software.

Technology will evolve.

Artificial intelligence will evolve.

Software engineering will evolve.

The identity of ForgeOS should remain constant.
